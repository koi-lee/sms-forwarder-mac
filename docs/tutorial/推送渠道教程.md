# 短信转发：推送渠道配置教程

按接收通知的平台选择下面的教程。推送渠道在转发宝的设备管理后台配置；Mac 串口助手通过 USB 查看设备日志、短信内容和推送结果，不代替设备发送通知。

整理日期：2026/09/25。Bark 已在本次设备上实测；其余渠道仅整理原说明书的教程入口与配置要点，尚未实测。不同固件的字段与支持范围可能不同，以实际设备界面为准。

## 配置前准备

- **Bark**：在自己的 iPhone 安装 Bark，取得自己的推送地址，在设备后台选择 Bark 通道并填写、保存。发送一条不含隐私的测试短信，对照手机收到的正文和 Mac 串口记录。实测配图见[截图归档](截图归档.md)。
- **飞书、钉钉、企业微信群**：准备自己管理的群及机器人配置。按对应教程创建机器人，再把所需地址和安全设置填入设备后台。这些教程含图片步骤，本次未逐张复核，不把群机器人是否仍可创建或当前平台限制写作已验证事实。
- **QQ 邮箱**：参考教程使用 SMTP，需准备邮箱地址和邮箱生成的授权码；授权码不是邮箱登录密码。原教程列出 `smtp.qq.com`、端口 `465`，并注明邮件通道仅使用 Wi-Fi。实际填写前核对邮箱当前设置及固件的服务器、端口、加密选项。
- **自定义请求**：准备接收服务要求的 URL 和请求正文。原教程示例使用 `{sender}`、`{timestamp}`、`{message}` 占位符；不要照抄真实密钥。示例时间前有固定的 `20` 前缀，是否需要它取决于固件输出，需用测试消息核对，避免年份重复。
- **Telegram Bot**：准备 Bot Token、目标 `chat_id` 及设备能够访问的服务地址。参考教程通过自定义请求调用 `sendMessage`；本项目未验证网络连通性与请求模板。
- **PushPlus**：参考教程使用 Token，并可指定接收渠道。原文含 HTTP 地址，正式配置时应核对服务当前支持的 HTTPS 入口及固件兼容性。
- **Server酱**：准备自己的 SendKey，按对应教程填写通道配置。
- **Gotify**：准备自己的 Gotify 服务地址与 Application Token，按对应教程填写。

以上是阅读教程前的准备说明，不是其他渠道已完成实测的承诺。

## 每增加一个渠道如何验收

1. 在设备后台只新增本次要验证的渠道，保存配置。
2. 向设备 SIM 卡发送一条容易辨认的测试短信，例如“飞书渠道测试01”。
3. 在目标应用检查是否收到，核对正文、发送号码和时间。
4. 如需排查，将设备通过 USB 数据线接入 Mac，连接串口助手，查看该消息和对应通道日志。串口显示推送成功后，仍以接收端实际收到为验收依据。
5. 记录设备固件、渠道、测试日期、接收结果及失败原因。截图打码后归档；机器人 Webhook、Token、SendKey、邮箱授权码和原始短信 PDU 不放进公开教程。

# 使用与排查

第一次使用请先按[快速上手](快速上手.md)完成连接和一条测试短信。

## 按现象排查

| 现象 | 先做什么 | 结果与下一步 |
| --- | --- | --- |
| 找不到设备配网 Wi‑Fi | 查看[短信宝设备后台登录与配网说明](短信宝设备后台登录.md)，核对热点名称及设备是否已连上家中 Wi‑Fi | 已连上路由器时热点可能关闭；说明书要求使用 2.4 GHz。不要因热点暂时不可见就恢复出厂或刷入来源不明的固件 |
| GitHub 找不到安装包 | 确认仓库是否已经公开、Release 是否已发布 | 使用 [Build 7 发布页](https://github.com/koi-lee/sms-forwarder-mac/releases/tag/v0.1.0-preview.7)，展开 Assets；选择 DMG，不要下载源码压缩包 |
| App 被系统阻止打开 | 阅读[安装教程](下载安装.md)中的系统提示处理 | 只对可信来源的应用单独允许打开，不关闭系统保护 |
| 列表没有设备 | 使用 USB 数据线，拔插后刷新，对比新增端口 | 仍没有时按设备厂商说明核对驱动，不随意安装陌生驱动 |
| 连接失败或提示占用 | 退出其他串口工具及本助手的重复副本，再重试 | 成功时显示“已连接” |
| 日志乱码 | 核对设备说明中的波特率，断开后调整再连接 | 仍乱码时提供脱敏截图、型号和固件版本反馈 |
| 有日志但没有短信卡片 | 在连接后从手机向设备 SIM 发送新短信 | 核对原始日志是否有收信事件；可能是固件输出或编码不受支持，旧短信不会自动导入 |
| 卡片显示“设备解析失败” | 展开“推送日志详情”，核对设备是否输出“PDU解析失败” | 这是设备日志报告的解析错误；Mac 助手不会修改固件或重试推送。联系设备卖家/固件维护方时只提供脱敏后的错误行和固件版本 |
| 卡片有短信但手机无推送 | 展开“推送日志详情”，核对设备网络与该渠道配置 | 在设备管理页排查推送；Mac 助手本身不发送 Bark 通知 |
| 内容显示不全 | 在对应区域滚动，或拖动两区之间的分隔线扩大短信区域 | 点“回到最新”查看最新短信；日志的“到底部”只影响日志区 |

## 这几个按钮是什么意思

串口是 Mac 与设备交换数据的通道，名称通常是 `/dev/cu.usbmodem…` 或 `/dev/cu.usbserial…`。端口名不是手机号码，也不是设备 IP。

波特率表示串口信号传输速率，需要与设备一致。本次设备使用 115200、8-N-1；速度不匹配可能乱码或没有输出。

HEX 关闭时，输入作为 UTF-8 文本发送；打开时输入两位十六进制字节，例如 `41 54`。这会向真实设备发送字节，只有知道设备指令含义时才使用。

CRLF 是回车加换行，对应 `0D 0A`。勾选后在发送内容后追加这两个字节，某些设备用它判断指令结束。查看日志或接收短信不需要手动发送。

## 看不到短信

先确认已连接正确串口、波特率一致且有新日志。连接前收到的短信不会自动导入。设备必须输出本工具支持的短信格式，才能生成卡片；不支持的内容仍可查看原始日志。

## 看不到推送结果

卡片根据接收短信后 60 秒内日志关联结果。先展开卡片详情，再对照原始日志和目标应用；并发事件可能关联不精确。

## 串口没有出现或被占用

换用支持数据的线缆并重新刷新。按 USB 芯片厂商说明核对驱动。关闭其他串口工具，同一端口通常不能同时被多个程序占用。

## 分享日志前

手机号、正文、验证码、Webhook、Token、IP、MAC 和原始 PDU 都可能包含隐私。遮盖可读手机号不能清除 PDU 中的同一信息；不要直接把原始日志提交到仓库或反馈表单。

## 反馈时提供什么

发到 service@starshoreai.com，或在仓库公开后提交 Issue：

- macOS 版本，以及“关于”中的应用版本。
- 设备型号、固件版本（找不到可写未知）、选择的波特率。
- 卡在哪一步、预期结果、实际看到的提示。
- 已遮盖隐私的截图；注明手机是否实际收到推送。

无需提供真实号码、Bark Key、密码或完整原始日志。先提供上述信息，再按具体问题补充经过脱敏的片段。

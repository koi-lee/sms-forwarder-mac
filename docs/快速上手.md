# 在 Mac 上看到第一条短信

目标：手机发一条测试短信后，在 Mac 看到发送号码、正文和发送时间，并在 Bark 等接收端核对推送。此教程针对已配置好的、输出格式受支持的短信转发设备。

## 1. 准备设备

- Mac 运行 macOS 13 或更新版本，已按[安装教程](下载安装.md)安装应用。
- 设备内装有可接收短信的 SIM 卡，你知道这张卡的号码。
- 设备已按其说明书完成供电、配网和推送渠道配置；先确认手机接收端能收到推送。短信宝配网热点和后台入口见[设备后台登录与配网说明](短信宝设备后台登录.md)；推送渠道见[渠道与设备配置入口](tutorial/推送渠道教程.md)。不同固件的管理地址和界面可能不同。
- 用支持数据传输的 USB 线连接 Mac。只有充电功能的线不能用于查看串口。

设备负责收短信、联网和推送；Mac 助手负责读取 USB 日志。日常转发可只给设备供电并保持其网络连接，无需一直插着 Mac。要用本助手实时查看，则需保持 USB 和应用连接。

## 2. 找到设备串口

打开「WIFI转发宝串口助手」，查看「设备串口」。推荐项中的“可能是短信宝（ESP32）”是线索，不是兼容保证。端口名称不是手机号，也不是 IP 地址。

认不出时：断开设备的 USB，点「刷新」记下列表；重新插入，再点「刷新」，选择新增的端口。多台同类设备请逐台接入核对。不要选择不认识的其他设备端口。

波特率按设备说明设置；本次实测设备为 **115200**。点「连接并监听」，预期右上角出现「已连接」，下方「接收日志」开始出现设备输出。部分设备仅在发生事件时输出，暂时安静不一定是故障。

## 3. 从手机发测试短信

保持助手连接。在手机的系统短信应用中，**向设备里面那张 SIM 卡的号码**发送：

> Mac 收信测试 01

不要在助手底部「手动发送」框输入这段测试短信。那个框是向硬件发送串口指令的入口；查看短信不需要使用它，也无需调整 HEX 和 CRLF。

连接前已经收到的短信不会自动导入。退出助手后，之前的短信卡片也不会恢复，所以请在连接后发送新的一条。

## 4. 核对三个结果

| 位置 | 应看到什么 |
| --- | --- |
| Mac「短信记录」 | 发送号码是发短信的手机号码，短信内容为测试正文；卡片分别显示 PDU 原始短信时间（未换算时区）和 Mac 助手观察时间 |
| 短信卡片及「推送日志详情」 | 设备报告的推送状态；有需要时展开详情，核对通道信息 |
| Bark 或你配置的接收端 | 实际收到同一条测试正文 |

「自动跟随最新短信」默认勾选；查看旧记录后可点「回到最新」。正文或详情看不全时，在短信区域滚动，或向下拖动短信与日志之间的分隔线。两个区域分别滚动、分别跟随。

卡片的「设备网络地址」是转发设备的地址，不是发信人的位置。推送结果根据随后 60 秒内日志关联；连续多条短信或多通道并发时可能混淆，应对照原始日志。绿色成功或 HTTP 200 不能代替手机实际收到。

如果卡片显示「设备解析失败」，表示设备日志报告了 PDU 解析问题；Mac 助手只显示设备报告，不会修复设备固件或自动重试。若同时显示相互矛盾的设备解析和推送结果，请展开详情并对照原始日志。

只看到日志、没有短信卡片，或手机没收到时，转到[按现象排查](使用与排查.md)。目前来电只在原始日志里查看，不会生成独立未接来电卡片。

## 5. 留下需要的记录

点击「保存日志…」，选择新文件并保存：会写入当前日志，并继续追加后续日志。单个文件达到 100 MiB 后，应用会停止向该文件追加，后续内容仍显示在窗口中；需要继续留档时请选择另一个文件。不要覆盖自己仍需保留的文件。退出应用后，重新运行需要重新选择保存文件；短信卡片本身不会持久保存。

需要结束监听时点「断开」。向别人反馈前先遮盖手机号、正文隐私和密钥；原始 PDU 也含有短信信息，不要直接上传完整日志。反馈材料清单见[使用与排查](使用与排查.md)。
